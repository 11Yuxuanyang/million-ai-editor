# HyperFrame Editorial Explainer

把抽象内容变成观众能看见的因果关系。主剪辑 Skill 负责全片、时间线和交付；本 Skill 只帮助设计需要解释的段落。

## 使用

1. 从已校对口播、人物表演和已登记素材写一句视觉论点：这一段最终要让观众看懂什么关系。
2. 读主 Skill 的 [画面能力索引](../hyperframe-video-editor/references/capability-index.md)，只展开相关的 technique、asset 和参考画面。
3. 为每个语义节拍选择人物、真实证据、生成解释、数据/系统动画或干净停留。真实证据负责证明，生成画面只解释、比喻或营造情绪。
4. 在本期 `MOTION-STORYBOARD.md` 写可见的进入、动作、结果和交接；采用成熟能力时附 technique/asset ID，不匹配时自主设计。
5. 用连续预览判断它是否真的讲清楚。只有被保留的设计才进入共享库。

## 事实与风格边界

- 真实素材和一手来源承担“证据”；生成画面只承担解释、假设、情绪或结构示意，不伪装成真实事件。
- 不虚构数据、页面、人物行为、产品能力或授权。生成文字不作为事实正文。
- 风格稳定来自构图优先级、克制配色、字体层级、证据感、材质和语义动作，不来自万能渐变、贴纸、圆角卡、白描边或统一弹跳。
- 色彩是栏目级基础能力：先按 `ground / content / structure / semantic accent` 分配角色，再按场景重排比例；默认一个结构色和最多一个有理由的语义强调色。固定角色读取项目 colorSystem，不靠旧视频反推。
- 生成解释段的舞台、材质和配色由本期决定。点阵、等高线或像素只在有语义工作时出现。
- 实拍只统一曝光、对比和白平衡，不改写肤色、证据色或素材身份；全屏白底、彩虹式 UI 和无语义霓虹不是默认选项。
- 精确 copy、数字、箭头、图表和关系线优先代码原生；生成资产保留自身色彩与 alpha，不用 CSS 偷换设计。

输出只回填本期分镜，不另建门禁表、检索追踪或独立审核链。
